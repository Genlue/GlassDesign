# 02 · 迁移矩阵

> 目的：把旧库 84 个工厂、8 个机制逐条安排到“第几批、什么难度、怎么处置”。
> 难度是**声明式重写成本**，不是旧代码的复杂度：S ≈ 纯 props→DOM；M ≈ 局部状态/事件/测量；L ≈ 拖拽/虚拟化/异步/复杂焦点/全局栈。
>
> **2026-11-15 材质变更**：`glass-lens` 的运行时 canvas/SVG 挂载已删除，改成构建期预计算贴图 + 静态 SVG filter。本表 §3.6 的 `Capsule` 现在多一个 `CapsuleSize` 固定档位；玻璃相关工作量从“重写挂载器”变为“生成静态资产 + 尺寸目录”。

## 6. 批次依赖

```text
P1 install / Theme / Icon / control_state
        │
        ▼
P2 基础控件 + Selection + CommandRegistry/UndoManager
        │                         │
        ├────────────► P3 布局与导航 ──► P4 浮层 ──► P5 表单
        │                                   │
        │                                   └──► P7 ToolbarOverflow / Customization
        └────────────► P6 数据（需要 Selection + 测量原语）
P3 Tabs ──► P7 DocumentTabs
P6 Selection ──► P6 DataTable / Tree
```

不能颠倒的三条：

1. **P4 的 `OverlayHost` 必须先于 P5**：Select、Combobox、DatePicker、ColorWell 全依赖浮层。
2. **P3 的 `Tabs` 必须先于 P7 的 `DocumentTabs`**。
3. **P2 的 `Selection` 必须先于 P2 的 `List`，再到 P6**。
