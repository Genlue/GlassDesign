# 00 · 探索：从 Golden Gate 到 GlassDesign

> 取证方式：逐文件读源码、跑统计脚本、查 `docs/09-architecture.md` 与 `docs/12-handover.md`、核对 `docs/component-manifest.json`。
> 本轮**没有**编译任何 Rust/WASM 代码（原因见 §15），所有结论都标注了证据位置。带“待验”的条目是风险，不是结论。

---

## 0. 结论（先看这五条）

1. **可搬走的是 CSS 与材质纯函数链，不是 JS 控件。** 10,204 行 CSS 里 51/62 个分区与框架无关；`glass-schema → glass-shape → glass-optics` 约 535 行是纯数值，能直接对照成 Rust。真正要重写的是 18,664 行命令式 DOM 组装与行为。
2. **难点不在样式，在“测量 + 焦点 + 浮层”。** 76 个控件文件里，前 12 个重型文件合计 9,094 行，占 49%；它们共享四类问题：同步测量、拖拽、异步、焦点还原。
3. **七个全局单例、两套模态栈，是声明式化最大的结构性阻力。** 不先合并层栈，任何“弹层组件化”都会做成两套互不相识的状态。
4. **`控件/` 能做到“一个文件夹复制”，但前提是样式与静态贴图都 `include_str!` 进 crate。** 只要还依赖仓库里的 `styles/` 相对路径，复制就不成立。
5. **选型建议 Leptos 0.8.23（CSR），Windows/WebView2 首发。** macOS/Linux 的 WebKit 不支持 `backdrop-filter: url()`，只能承诺 CSS 兜底，不能承诺同一视觉。

## 0.5 方向变更（2026-11-15 16:10）

材质方案在 P1 中途改了两次，最终定稿为：

1. **不做运行时渲染 core。** 删除 `glass-lens` 的 canvas / SVG 运行时挂载，不注入任何 JavaScript。
2. **构建期预计算。** `scripts/build-glass.mjs` 用 `glass-schema / glass-shape / glass-optics` 算出位移图与高光图，编码 PNG，内嵌进 `控件/assets/glass-defs.svg` 的静态 `<filter>`。
3. **运行时只有 CSS。** `backdrop-filter: blur(...) saturate(...) url(#gd-glass-capsule-180)`；`install()` 只注入 CSS 与静态 SVG。
4. **固定尺寸档。** 实测 Chromium 的 `feImage` 不能可靠拉伸预计算贴图；套到不同尺寸会留下硬切。因此胶囊按 34 / 112 / 180 三档生成，`CapsuleSize::Auto` 走纯 CSS 兜底。

实测结论（本机 Chrome，WebView2 同源 Chromium）：

- `backdrop-filter: url(#filter)` 可用：测试滤镜把渐变区变灰，证明滤镜真的作用到背板。
- `feImage width="100%"` 不会按元素框拉伸；必须给精确 px，且元素尺寸与贴图一致。
- 静态 filter 在 180×34 胶囊上能完整覆盖，边缘高光、模糊正常；折射幅度受 CSS 涂层影响，偏克制。

代价：**真折射只在固定档位成立**；自适应宽度只能走 CSS 兜底。要覆盖更多尺寸，就加档位，不要指望一张图通吃。

## 1. 现状是什么：五个平面

旧库不是“一个框架”，是五层拼起来的系统。迁移判断必须按层做，不能按文件做。

| 平面 | 载体 | 规模 | 依赖框架 | 迁移判断 |
|---|---|---|---|---|
| **表现面** | `styles/**` | 10,204 行；62 个分区 + 4 个入口 | 无 | **原样保留**，按控件切分 |
| **材质面** | `core/glass-schema/shape/optics/lens/refraction` | core 共 2,537 行；8 个玻璃面、14 项参数 | 弱（DOM/CSS） | **纯函数保留，构建期生成静态 filter** |
| **结构面** | `scripts/ui/**` | 76 文件 18,664 行；84 个工厂 | 强（命令式建 DOM） | **重写为 Rust 组件** |
| **行为面** | `_shared/*` + `core/{spring,scrollbar,dom}` | 层栈/选择/命令/撤销/弹簧/滚动条 | 强（全局单例） | **逻辑对照，代码重写** |
| **宿主面** | `electron/*` + `core/platform.js` | 2 个主进程文件 + 6 个 IPC 通道 | Electron | **换成 Tauri 对等实现** |

三个补充事实：

- `dev/` 下 11 个页面、766 条断言 × 2 遍，是**行为规格**，不是演示。迁移时它们比文档更可信。
- 根目录 `index.html`（1.15 MB）是 `scripts/build-preview.mjs` 的生成物，不是源码入口。迁移不要以它为准。
- `scripts/catalog.mjs` 生成的 103 项清单只证明“导出存在”，不证明交互完备；这一点旧文档自己写了。

## 2. 四条不变量（迁移必须守住）

这四条是旧库真正的“设计契约”。守住它们，视觉与手感才不会在 Rust 里走样。

1. **令牌唯一来源。** 控件只消费 `styles/tokens.css` 的变量，不写字面色值、字号、圆角、阴影。证据：`tokens.css` 头注释；`theme.js` 只写变量，不写规则。
2. **材质由固定尺寸档触发。** 一块玻璃 = 类名 / `data-size` + 一个**静态** SVG 滤镜；贴图在构建期算好，运行时不计算。证据：`scripts/build-glass.mjs`、`控件/assets/glass-defs.svg`。
3. **状态契约统一。** 有值控件一律 `set / value / setDisabled / setInvalid / setReadonly`；释放一律 `dispose()` 且幂等。证据：`_shared/control.js`、`_shared/disposer.js`。
4. **CSS 层叠顺序即契约。** `01-62` 的编号是加载顺序，不是分类；`24-glass-renderer` 必须晚于材质与控件分区。证据：`components.css` 头注释、`09-architecture.md` §样式分区。

迁移后的对应关系：

| 旧契约 | 新契约 |
|---|---|
| 令牌唯一来源 | 不变，Rust 只写 CSS 变量与类名 |
| 材质由固定尺寸档触发 | 组件只写 `data-size`；贴图构建期生成 |
| `set / value / dispose` | `Signal` + `Callback` + `on_cleanup` |
| CSS 顺序即契约 | 不变，CSS 打包时保持 01-62 顺序 |

## 3. 依赖脉络

```text
dev/showcase.js（2,683 行） + 场景页 workbench / files / crud / tasks
        │  只用 kit.js
        ▼
scripts/ui/{controls,forms,surfaces,navigation,content,collections,overlays,appearance,panels}
        │  显式 import，禁止反向 import kit/index
        ▼
_shared/{overlay,commands,selection,disposer,control,lifecycle}
        │
        ▼
core/{dom,icons,theme,spring,scrollbar,glass-shape,glass-optics,glass-lens,refraction,platform}
        │
        ├──────────────► styles/{tokens → base → layout → components(62)}
        │                 控件不 import CSS，只靠类名与选择器对接
        ▼
electron/{main.mjs, preload.cjs} ──IPC──► core/platform.js ──► window.gg
```

三个容易看错的地方：

- **CSS 不在 import 图里。** 控件与样式是“约定耦合”（类名），不是模块耦合。这是 CSS 能原样搬走的原因，也是类名不能随手改的原因。
- **`platform.js` 是唯一宿主接触面。** 6 个通道 + 2 个事件，全部经 `window.gg`。Tauri 迁移只需要替换这一层，不该扩散到控件。
- **`theme.js` 同时是状态、CSS 写入器、持久化三件事。** 它不是“主题工具”，是隐藏的全局单例，必须拆。

## 5. 五个真正的耦合点

### 5.1 命令式建树：DOM 就是返回值

`h()` 直接 `document.createElement`，控件把 `HTMLElement` 当返回值，状态方法直接挂在节点上（`el.set = ...`）。84 个工厂全是这个形状。

- 影响：无法“描述 → diff”，也没有“props 变了自动更新”。声明式迁移不是换语法，是换所有权：**节点归框架，控件只描述**。
- 例外：`openMenu / toast / tip` 这类“一次性命令”天然是命令式，应该保留为助手，不要硬做成组件状态。

### 5.2 七个全局单例 + 两套模态栈

源码里能点名的全局单例：

| 单例 | 位置 | 作用 |
|---|---|---|
| `layers` | `_shared/overlay.js` | 层栈真相，z-index/焦点/关闭顺序 |
| `listening` | 同上 | document 上的两个永久监听 |
| `rootMenu` | `overlays/menu.js` | 同一锚点二次点击收起 |
| `activePopover` | `overlays/popover.js` | 全局互斥 |
| `toastHost` | `overlays/toast.js` | 常驻宿主，FLIP 补间 |
| `tipEl / tipTimer` | `overlays/tooltip.js` | 全库唯一提示 |
| `dialogStack` | `overlays/dialog.js` | **与 `layers` 并列的第二套栈** |

`Dialog / Sheet` 用 `dialogStack` 算 z-index（`500 + (n-1)*20`），`Menu / Popover` 用 `layers` 算（`900 + level*20`）。两套栈互不知道对方存在，只是数值上刚好不冲突。

- 迁移必须先合并成**一个 `OverlayHost`**（thread_local + 栈），否则 Rust 侧会出现同样的双栈。
- `document.body.append` 的调用点有 8 处：Dialog、Sheet、Menu（含子菜单）、Popover、Toast、Tooltip、ToolbarCustomization。声明式侧统一走一个 `<Portal>` 宿主。

### 5.3 同步测量：一半代码在跟布局打交道

前 12 个重型文件（9,094 行，49%）：

| 文件 | 行数 | 测量/交互 |
|---|---:|---|
| `collections/data-table.js` | 1,347 | 列宽拖拽、列序、虚拟行、就地编辑 |
| `forms/date-picker.js` | 1,075 | 三层视图、roving 焦点、浮层 |
| `appearance/color-well.js` | 890 | SV 面板/色相/透明度三处拖拽、色彩空间 |
| `forms/combobox.js` | 838 | 虚拟滚动、异步请求、焦点留在输入框 |
| `forms/token-field.js` | 791 | token 与输入框焦点迁移、异步建议 |
| `panels/split-view.js` | 763 | 约束求解（8 轮迭代）、折叠记忆 |
| `collections/collection-view.js` | 719 | 高度缓存、前缀和、滚动锚点 |
| `panels/status-bar.js` | 680 | 任务计时器、朗读节流 |
| `forms/time-picker.js` | 662 | 光标分段编辑、数字缓冲 |
| `navigation/document-tabs.js` | 620 | 拖拽重排、会话恢复 |
| `collections/tree-view.js` | 620 | 懒加载、扁平可见序列 |
| `navigation/toolbar-customization.js` | 568 | 浮层拖拽、可见集持久化 |

浏览器 API 的分布：`ResizeObserver` 14 个文件、`getBoundingClientRect` 17 个、`requestAnimationFrame` 20 个。

- Rust/WASM 里**没有同步布局**。`offsetHeight` 读一次就是一次强制回流，而且 Leptos 的渲染是异步的。
- 策略只能是三条：**CSS 优先（grid/flex/容器查询）→ 两阶段渲染（先量后定）→ 接受一帧延迟**。这不是“翻译代码”能解决的。

### 5.4 焦点还原：声明式重建天然丢焦点

至少 8 个控件在重绘后手工把 `document.activeElement` 搬回去：DocumentTabs、Tabs、Pagination、DataTable、CollectionView、TreeView、ToolbarOverflow、Sheet。虚拟滚动还会把持有焦点的节点直接丢弃。

- 旧库靠“先记住 key，重建后 `focus()`”兜底；新库必须把它变成契约：**焦点用 key 标识，重建后按 key 恢复**。
- 这是键盘可用性的命门，不是细节。迁移验收必须逐控件测 Tab / 方向键 / Esc。

### 5.5 宿主特化：窗口壳与材质都假设 Electron

- 透明 + 无边框 + `titleBarStyle: 'hidden'`（`electron/main.mjs:61-84`）。
- `-webkit-app-region: drag/no-drag`（`base.css:236-245`）只对 Chromium 生效；Tauri 用 `data-tauri-drag-region`。
- `data-focused` 由 IPC 焦点事件驱动（`platform.js:66-89`），红绿灯与文字层级读它。
- `traffic-lights` 是 macOS 26 实测的 145 行 CSS，不是通用窗口装饰。
- 全库 CSS **没有**消费 `[data-titlebar]`，`platform.js` 写它属于悬空钩子。

### 5.6 主题是隐藏的全局单例

`theme.js` 做三件事：状态（mode/accent/glass/shadow/stroke/optics）、写 CSS（`<style id="gg-optics">` 全量覆写）、持久化（`localStorage['lumina.appearance.v8']`）。

- `applyOptics()` 每改一次参数就重写整段 `<style>`；8 个面 × 14 项。
- 渲染层直接读 `theme.getOptics()`（JS 对象），CSS 兜底读变量；两条路数值同源，但读取方向相反。
- 迁移建议：**Rust 只写变量，CSS 只读变量**。静态 filter 的位移/高光固定，涂层与模糊仍由 `--lg-*` 驱动。

| **删除** | `glass-lens.js` 的 `resolveBlur`、生命周期注册表、expando | 没有运行时透镜，整段不需要 |

## 7. 目标形态：`控件/` 作为唯一复制单元

### 7.1 目录

```text
控件/                              ← 复制这一个文件夹
├── Cargo.toml                     package = "glass-design-widgets"
├── README.md                      复制 / 替换 / 版本
├── 变更.md                        破坏性变更逐条记
├── src/
│   ├── lib.rs                     prelude + install() + VERSION
│   ├── base/                      dom / class / icon / theme / host / overlay
│   ├── widgets/                   button / field / switch / slider …
│   ├── layout/                    card / section / row / split / app_shell
│   ├── nav/                       nav_column / toolbar / tabs / breadcrumb
│   ├── data/                      list / table / tree / collection / data_table
│   ├── form/                      select / combobox / date / time / file / token
│   ├── overlay/                   menu / dialog / sheet / toast / popover
│   └── panel/                     inspector / drawer / status_bar / document_tabs
├── css/                           tokens / base / layout / components(62)
├── assets/                        glass-defs.svg（预计算贴图 + 静态 filter）
└── assets/                        icons.rs（97）/ 字体说明
```

顶层目录名用中文（复制单元的名字），内部模块用 ASCII（跨平台、`cargo doc`、脚本都稳）。这是有意的：**中文只出现在人看的地方，不出现在工具链里。**

### 7.2 三种消费姿势

| 消费方 | 拿走什么 | 怎么用 |
|---|---|---|
| Rust / Tauri 项目 | 整个 `控件/` | `glass-design = { path = "vendor/控件" }`；`install()`；`view!` 拼装 |
| 原生 HTML/JS 项目 | `控件/css` + `控件/assets` | `<link>` + 内联静态 SVG；用同一套类名与 `data-size` |
| 旧 JS 项目 | 不拿 | 继续用 `Golden Gate HTML Design`，冻结 |

第二种姿势是刻意保留的：它让 Lumina 这类现有 Tauri + 原生 JS 项目不用重写就能吃到新材质与样式，也让“控件库”不是只能服务 Rust。

### 7.3 复制与替换

复制：

1. 把 `控件/` 整个拷到目标项目（例如 `vendor/控件`）。
2. `Cargo.toml` 加 `glass-design = { path = "vendor/控件" }`。
3. `main()` 里调一次 `glass_design::install()`，然后 `view!`。

替换：

1. 用新版本覆盖 `vendor/控件/`。
2. `cargo build`（path 依赖会自动重编）。
3. 读 `控件/变更.md`，处理破坏性变更；没有就是零改动。

### 7.4 版本与破坏性变更

- `控件/Cargo.toml` 版本 + `pub const VERSION` 双写，`install()` 把它写到 `data-gd-version`，页面可自查。
- 语义化版本：新增 prop 是 minor；改 props 形状、删组件、改 DOM 契约是 major。
- 不承诺“任意版本可热替换”；承诺“同 major 内覆盖文件夹即可”。
- 每次 major 在 `变更.md` 写：删了什么、为什么、旧写法怎么改。

## 8. 声明式契约（摘要）

完整签名与示例见 [`01-控件契约.md`](01-控件契约.md)。这里只列迁移映射。

| 旧 API | 新契约 | 说明 |
|---|---|---|
| `Button({label, onClick})` | `<Button label="…" on_click=… />` | 组件 |
| `el.set(v)` | `value: Signal<T>` + `on_change: Callback<T>` | 受控；唯一真相在调用方 |
| `el.value()` | `signal.get()` | 不再从 DOM 读 |
| `el.setDisabled(v)` | `disabled: MaybeProp<bool>` | 属性 |
| `el.setInvalid(v)` | `invalid: MaybeProp<bool>` | 属性 |
| `el.dispose()` | `on_cleanup` | 框架管生命周期 |
| `openMenu()` | `open_menu(req) -> MenuHandle` | 命令式保留 |
| `toast()` | `toast(req) -> ToastHandle` | 命令式保留 |
| `tip()` | `<Tooltip>` 或 `tip()` | 二者皆可 |
| `createSelection()` | `Selection<T>` | 纯逻辑，可单测 |
| `CommandRegistry` | `CommandRegistry` | 纯逻辑 |
| `UndoManager` | `UndoManager` | 闭包 `revert/apply` 换成命令对象/补丁 |
| `openLayer` | `OverlayHost::open` | 全局唯一栈 |
| `theme.*` | `Theme` context | 只写 CSS 变量 |
| `platform.*` | `host::*` | Tauri 对等实现 |

三条边界：

1. **组件不查 DOM。** 需要测量/聚焦时用 `NodeRef`，不用 `querySelector`。
2. **组件不挂 body。** 浮层走 `<Portal>` + `OverlayHost`，组件本身不 `append`。
3. **组件不存全局状态。** 除 `OverlayHost`、`Theme` 两个 `thread_local`，其余状态归调用方。

## 9. 选型：为什么是 Leptos 0.8.23

| | **Leptos 0.8.23** | Dioxus 0.7.10 | Yew 0.23 | 自建 wasm-bindgen | 保留 JS |
|---|---|---|---|---|---|
| 声明式粒度 | 细粒度 signals，无 VDOM | signals + VDOM | VDOM | 自己写 | 无 |
| 与 Tauri 集成 | 任意静态站点，无 CLI 依赖 | 自带 desktop/CLI/asset，和 Tauri 职责重叠 | 任意静态站点 | 任意 | 现成 |
| 维护状态 | 0.8.23（2026）；作者 2026-05 声明“轻维护”；0.9 rc | 0.7.10（2026-07），活跃；0.8 alpha | 0.23（2026-03），慢 | 自担 | 旧库已冻结 |
| 迁移成本 | 中 | 中高 | 中 | 高 | 零 |
| 运行时体积 | 小 | 中 | 中 | 最小 | 中 |
| 结论 | **推荐** | 备选 | 不推荐 | 不推荐 | 不满足要求 |

推荐理由（按权重）：

1. `view!` 与 HTML 结构最接近，10,204 行 CSS 的类名可以一对一落进去，迁移时“看旧模板写新模板”最省心。
2. 细粒度 signals 正好对应旧库的 `set/value` 契约：一个值一个 signal，不需要 VDOM diff，也不需要“整页重渲染”。
3. 不绑定 CLI/路由/资源系统。Tauri 负责窗口与资源，Leptos 只负责 DOM，职责不重叠。
4. 可以 CSR（Tauri 内），也可以 SSR 出静态画廊，`index.html` 的生成路径更短。

为什么不是另外四个：

- **Dioxus**：自身有 desktop runtime（wry）、`dx` CLI、asset 系统，和 Tauri 的职责重叠；要用在 Tauri 里只能用 `dioxus-web`，等于付了两套工具链的成本。0.8 还在 alpha。
- **Yew**：VDOM + 较慢的发布节奏；对“大量测量与焦点”的控件没有优势。
- **自建 wasm-bindgen**：等于在控件库里再造一个框架。76 个控件的复杂度已经够高，不该再养一套响应式运行时。
- **保留 JS**：直接违背“tauri + rust + 声明式”的目标，而且会出现两套真相。

维护风险的处置：

- 锁 `=0.8.23`，不追 0.9 rc；`base/reactive.rs` 只 re-export 用到的 12 个类型，升级时改一处。
- 不用 router / SSR / server functions / meta；依赖面越小，升级越轻。
- 组件公开 props 用**自己的枚举与结构体**，不把 `leptos::` 类型暴露给调用方；将来换框架，调用方代码不动。
- 真到无法维护，`控件/` 是 path 依赖，可以整体 fork；这是“文件夹即库”的额外好处。

## 10. 宿主对等：Electron → Tauri

| Electron | Tauri 2 | 备注 |
|---|---|---|
| `window:minimize` | `Window::minimize()` | 直接对等 |
| `window:toggle-maximize` | `is_maximized()` + `maximize/unmaximize` | 返回值要自己拼 |
| `window:close` | `Window::close()` | |
| `window:titlebar-mode` | 创建时 `decorations` | 运行期改装饰要重建窗口 |
| `shell:open-in-explorer` | `opener` 插件 / `show_in_folder` | 可能需要权限配置 |
| `window:focus / blur` | `WindowEvent::Focused` | 事件模型不同，需在 Rust 侧转成信号 |
| 透明 + `frame:false` | `transparent: true` + `decorations: false` | Windows 上透明与阴影/缩放边框需实测 |
| `-webkit-app-region: drag` | `data-tauri-drag-region` | CSS 钩子必须改 |
| `gg://` 自定义协议 | `asset` 协议 / 自定义协议 | ESM 不能走 `file://`，这条必须保留 |
| preload `window.gg` | `withGlobalTauri` / `invoke` | 统一收进 `js/host.js` |

材质矩阵（决定“首发平台”）：

| 宿主 | 材质路径 | 结果 |
|---|---|---|
| Windows WebView2（Chromium） | 静态 SVG filter + `backdrop-filter: url(#…)` | 已在本机 Chrome 验证滤镜生效；WebView2 待 Tauri 实机截图 |
| macOS WKWebView | 不支持 `url()` | 只能 CSS 兜底，折射/色散消失 |
| Linux WebKitGTK | 视版本 | CSS 兜底，且 `:has/color-mix` 可能缺失 |

结论：**Windows 首发，macOS/Linux 只承诺“可用的 CSS 兜底”，不承诺像素一致。** 如果要求三端一致，得把静态折射 filter 降级成纯 CSS（损失折射），这是产品决策，不是技术细节。

## 11. 预览页与验收

`index.html` 是生成物，不是手写页：

1. `cargo build --target wasm32` + `wasm-bindgen --target web` 产出 wasm 与 JS glue。
2. `scripts/build-css.mjs` 把 `控件/css` 按 01-62 顺序拼成单文件（保留 `@import` 语义）。
3. `scripts/build-preview.mjs` 把 CSS、`assets/glass-defs.svg`、wasm（base64）、loader 内联进一个 HTML。
4. `wasm-bindgen` 的 `initSync(bytes)` 接收 base64 解码后的字节，绕开 `file://` 的 fetch 限制。

预估体积：CSS ≈ 280 KB、静态 SVG ≈ 60 KB、wasm ≈ 1.5–2.5 MB。超过 4 MB 就退回 `dist/` + 本地静态服务器，不再坚持单文件。

验收分三层：

| 层 | 手段 | 判据 |
|---|---|---|
| 纯逻辑 | `cargo test` | 玻璃参数归一化、选择模型、命令/撤销、尺寸求解 |
| DOM 行为 | 复用旧库 `scripts/tools/browser-check.mjs`（CDP） | Tab/方向键/Esc/焦点还原/虚拟滚动 |
| 视觉 | 画廊截图 + 旧库同页对照 | 关键面（顶栏/面板/菜单/模态）无肉眼级偏差 |

每批控件的出口条件：**旧库对应断言子集全过 + 新画廊有活体样例 + 文档有签名**。三条缺一不算完成。
