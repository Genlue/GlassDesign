# 01 · 控件契约

> 这份文档定义 `控件/` 对外承诺什么、不承诺什么。
> 迁移时逐条对照：**旧库的 103 项 API 不是都要有对应物**，但每一条都要有去处（合并、降级、删除、或保留为助手）。

---

## 1. 目标与边界

**目标**：让调用方用 `view!` 拼界面，不碰 DOM、不碰全局单例、不碰测量。

**边界**：

- 只做桌面界面，不做路由、数据请求、状态容器、表单引擎之外的领域逻辑。
- 只承诺 Windows/WebView2 的完整视觉；macOS/Linux 承诺“可用 + CSS 兜底”。
- 不承诺 DOM 结构稳定；承诺类名、`data-*`、ARIA、键盘行为稳定。
- 不承诺“任意版本热替换”；承诺同 major 内覆盖文件夹即可。

## 2. 一个完整页面（目标写法）

```rust
use leptos::prelude::*;
use glass_design::prelude::*;

#[component]
fn Gallery() -> impl IntoView {
    let query = RwSignal::new(String::new());
    let density = RwSignal::new(SegmentedValue::Regular);
    let saved = RwSignal::new(false);

    view! {
        <AppShell>
            <NavColumn>
                <NavSection label="控件" />
                <NavItem icon=IconName::Grid label="基础" selected=true />
                <NavItem icon=IconName::Sliders label="表单" />
                <NavItem icon=IconName::Table label="数据" />
            </NavColumn>

            <Main>
                <Toolbar>
                    <ToolbarTitle title="基础控件" subtitle="按钮、输入、开关" />
                    <Capsule>
                        <SearchField value=query placeholder="搜索控件" />
                        <Segmented options=vec![
                            SegmentedOption::new("紧凑", SegmentedValue::Compact),
                            SegmentedOption::new("常规", SegmentedValue::Regular),
                        ] value=density />
                    </Capsule>
                </Toolbar>

                <ScrollArea>
                    <Card>
                        <SectionTitle>"按钮"</SectionTitle>
                        <Row label="主要操作">
                            <Button
                                label="保存"
                                variant=ButtonVariant::Primary
                                on_click=move |_| saved.set(true)
                            />
                            <Button label="取消" variant=ButtonVariant::Plain />
                        </Row>
                        <Row label="状态" hint="保存后显示提示">
                            <Show when=move || saved.get()>
                                <Badge label="已保存" variant=BadgeVariant::Success />
                            </Show>
                        </Row>
                    </Card>
                </ScrollArea>
            </Main>
        </AppShell>
    }
}
```

这段代码要能说明四件事：**布局是组件、状态是 signal、事件是 callback、没有一句 DOM 操作。**

## 3. 组件形态与命名

- 组件名用英文 PascalCase，与旧库、CSS 类名保持一致：`Button`、`DataTable`、`NavColumn`。
- props 用 snake_case：`on_click`、`page_size`、`empty_text`。
- 变体用枚举，不用字符串：`ButtonVariant::Primary`，内部映射到 `c-btn--primary`。
- 尺寸用枚举：`Size::Sm / Md / Lg`，默认 `Md`（不写类）。
- 所有公共类型从 `glass_design::prelude::*` 导出；子模块只作为组织手段，不作为调用入口。
- 一个控件一个文件；复合控件（`NavItem` 与 `NavGroup`）可以同文件，但必须分别导出。

**不做的命名**：

- 不用 `XxxWidget` / `XxxComponent` 后缀——库本身就是控件库，重复无意义。
- 不把旧库的 `openXxx` 直接改成组件名——命令式助手保留动词开头。

## 4. Props 约定

| 类别 | 类型 | 约定 |
|---|---|---|
| 文本 | `#[prop(into)] String` / `&'static str` | 短标签用 `&'static str`，可拼接的用 `String` |
| 可选文本 | `#[prop(into, optional)] Option<String>` | 空字符串视为 `None`，由组件归一 |
| 布尔（静态） | `bool` | 不会变的开关 |
| 布尔（响应式） | `MaybeProp<bool>` | 可能随 signal 变；默认 `false` |
| 值 | `Signal<T>` | 受控值；组件只读 |
| 事件 | `Callback<T>` | 只在用户动作时触发 |
| 列表 | `Signal<Vec<Item>>` 或 `Vec<Item>` | 数据量大时用 signal，避免整体克隆 |
| 样式附加 | `#[prop(into, optional)] class: String` | 只追加，不替换组件类名 |
| 节点引用 | `NodeRef<html::Div>` | 仅用于测量/聚焦，不作为内容通道 |
| 插槽 | `Children` / `ChildrenFn` | 默认插槽；命名插槽用结构体字段 |

规则：

1. **不暴露 `leptos::` 类型给调用方**（`Signal`/`Callback` 除外，它们是契约的一部分）。枚举、选项结构体都定义在 `控件/` 内。
2. **不给 props 加 `style: String`。** 需要局部尺寸时用语义 prop（`width`、`rows`、`min_width`），由组件映射到类或 CSS 变量。
3. **不用 `impl IntoView` 当数据通道。** 列表项用结构体（`MenuItem`、`TableColumn`、`NavNode`），不用任意视图；否则组件无法做键盘与虚拟化。
4. **默认值写在组件签名里**，不藏在 CSS 里。

## 5. 受控与非受控

旧库的 `set/value` 是“组件持有值，外部推拉”。新契约反过来：**调用方持有值，组件只发事件**。

```rust
// 受控：唯一真相在调用方
<Field value=query on_input=move |v| query.set(v) />

// 非受控：组件内部持有初始值，仍然发事件
<Field initial="未命名" on_input=move |v| log(v) />
```

约定：

- 同时给 `value` 与 `initial` 时，`value` 优先，`initial` 被忽略（不报错，文档写明）。
- `on_change` 只在**用户动作**后触发；程序改 `value` 不触发，避免回环。
- `on_input` 与 `on_change` 的区别保留：拖动/输入过程发 `on_input`，提交/失焦/松手发 `on_change`。
- 校验状态（`invalid`）由调用方给，组件不自己判断业务规则；`FormField` 例外，它承接 `validate`。
- 禁用/只读/忙碌都是 props，不是方法。

## 6. 复合组件与 Context

三类复合关系，处理方式不同：

| 关系 | 例子 | 方式 |
|---|---|---|
| 父子结构 | `NavColumn` + `NavItem`、`List` + `ListRow` | 纯组合，不共享状态 |
| 兄弟协作 | `Tabs` + `TabPanel`、`RadioGroup` + `Radio` | Context 传 `selected` / `name` |
| 表单编排 | `Form` + `FormField` | Context 注册字段、收集值、串行校验 |

规则：

- Context 只在**必须跨层级**时用；能用 props 就不用 Context。
- Context 的 key 用私有类型，不污染调用方命名空间。
- 复合组件的子项必须能在任意深度；不允许“只能直接子节点”的隐式限制（旧库的 `Form` 靠 `querySelectorAll` 扫描，就是要避免的反例）。

---

## 7. 插槽

- 默认插槽：`children: Children`。
- 需要重复渲染的插槽：`ChildrenFn`（例如 `Empty` 的 action、`Dialog` 的 footer）。
- 命名插槽用结构体字段，不用元组位置：

```rust
<DataTable
    columns=columns
    rows=rows
    toolbar=view! { <Button label="新建" /> }.into_view()
/>
```

- 插槽内容不能依赖组件内部 DOM；组件也不假设插槽里有什么。

## 8. 测量与 NodeRef

Rust/WASM 没有同步布局。所有测量必须遵守：

1. **先 CSS，后测量。** 能用 grid/flex/容器查询解决的，不写 JS 测量。
2. **测量放 `Effect` 或 `ResizeObserver`**，不放在 render 函数里。
3. **两阶段渲染**：第一帧给稳定骨架（固定行高/占位），测量后再定位；不允许“先渲染再跳一下”。
4. **测量结果进 signal**，由 signal 驱动样式；不要直接写 `style.width`（除拖拽中的临时值）。
5. **NodeRef 只给需要测量的元素**，不是每个节点都挂。

```rust
let track = NodeRef::<html::Div>::new();
Effect::new(move |_| {
    let Some(el) = track.get() else { return };
    let ro = ResizeObserver::new(move |entries, _| { /* 写入 signal */ });
    ro.observe(el);
    on_cleanup(move || ro.disconnect());
});
```

## 9. 生命周期

| 旧 | 新 |
|---|---|
| `dispose()` 手动调用 | `on_cleanup` 自动调用 |
| `createDisposer()` 登记表 | `on_cleanup` + 局部 guard |
| `disposeComponentTree(root)` | 不需要；框架卸载即释放 |
| 玻璃 `disposeGlassTree` | 静态 filter 没有运行时实例，不需要释放 |

规则：

- 组件必须**幂等清理**：observer 断开、计时器清除、全局栈条目移除。
- 清理不能摘 DOM（框架负责）；静态材质没有内联状态要清。
- 异步任务用 `on_cleanup` 取消；请求类用 generation/abort 双保险（旧库 Combobox 的做法保留）。

## 10. 浮层契约

浮层分两类，边界必须清楚：

| 类型 | 例子 | 写法 | 原因 |
|---|---|---|---|
| **状态型** | Dialog、Sheet、Drawer、Popover | 组件 + `open: Signal<bool>` | 可见性本来就是状态 |
| **命令型** | Menu、ContextMenu、Toast、Tooltip | 助手函数 + 句柄 | 由一次点击触发，没有“常驻状态” |

统一底座：`OverlayHost`。

```rust
pub struct OverlayHost { /* thread_local 单例 */ }

impl OverlayHost {
    pub fn open(&self, req: LayerRequest) -> LayerHandle;
    pub fn close_top(&self);
    pub fn depth(&self) -> usize;
}
```

契约：

- **只有一套栈。** `Dialog`、`Sheet`、`Menu`、`Popover`、`Toast`、`Tooltip` 全部入同一栈；z-index 由深度算，不再有 `dialogStack`。
- **Portal 唯一。** 所有浮层挂到 `#gd-overlay-root`，组件不 `append` 到 body。
- **焦点归还。** 打开时记住触发器，关闭时归还；触发器不在文档里则归还到父层。
- **Esc 只关一层。** 由 `OverlayHost` 统一处理，子层不各自监听。
- **`inert` 快照。** 打开模态层时记录背景节点的原值，关闭时逐节点恢复，不整片清除。
- **定位求解器唯一。** `position_layer(anchor, placement, align)` 一个实现，Menu/Popover/Select/Combobox/DatePicker 共用。

命令型助手的句柄：

```rust
let menu = open_menu(MenuRequest::new(anchor).items(items));
menu.close();          // 幂等
let _ = menu.is_open(); // 只读
```

## 11. 主题契约

```rust
#[derive(Clone, Copy)]
pub struct Theme { /* signals */ }

impl Theme {
    /// 在应用根调用一次；内部 provide_context。
    pub fn provide() -> Self;
    pub fn mode(&self) -> ReadSignal<ThemeMode>;
    pub fn set_mode(&self, mode: ThemeMode);
    pub fn accent(&self) -> ReadSignal<Accent>;
    pub fn set_accent(&self, accent: Accent);
    pub fn glass(&self) -> ReadSignal<f32>;      // 0..1
    pub fn set_glass(&self, v: f32);
    pub fn optics(&self, surface: GlassSurface) -> Optics;
    pub fn set_optics(&self, surface: GlassSurface, patch: OpticsPatch);
}
```

规则：

- Theme **只写 CSS 变量与根属性**，不写规则、不注入 `<style>`。
- 变量名沿用旧库：`--accent`、`--accent-rgb`、`--lg`、`--lg-band`、`--lg-amount`、`--glass-blur-k`……CSS 与静态 filter 都认这套名字，替换成本最低。
- 主题持久化走 `Storage` trait：默认 `localStorage`；Tauri 项目可注入 `tauri-plugin-store` 实现。
- 「跟随系统」用 `matchMedia('(prefers-color-scheme: dark)')` + 宿主焦点事件；宿主能提供真实系统主题时优先用宿主值（旧库 `setSystemTheme` 的语义保留）。

## 12. 安装、注入与材质

```rust
pub const VERSION: &str = env!("CARGO_PKG_VERSION");

pub struct InstallReport {
    pub styles: bool,
    pub glass_defs: bool,
    pub version: &'static str,
}

pub fn install() -> InstallReport;
```

- 只注入两样东西：`<style id="gd-styles">` 与 `<div id="gd-glass-defs">`（内含静态 SVG filter）。
- 幂等；重复调用返回已有结果。
- 没有 `<script>`、没有 canvas、没有 WebGL。
- 不创建窗口、不读文件、不发网络请求。
- CSP 严格的项目可以不用 `install()`，自己 `<link>` `css/glass.css` 并把 `assets/glass-defs.svg` 内联到页面即可。

### 12.1 材质：固定尺寸档

真折射由**构建期预计算**的位移图 + 高光图完成，运行时只挂 CSS：

```css
.c-capsule[data-size="180"] {
  backdrop-filter: blur(12px) saturate(180%) url(#gd-glass-capsule-180);
}
```

Chromium 的 `feImage` 不能可靠地把贴图拉伸到任意尺寸。**贴图尺寸必须与元素尺寸一致**，所以玻璃组件按档位做：

| 档位 | 尺寸 | CSS |
|---|---|---|
| `CapsuleSize::Round` | 34 × 34 | `.c-capsule--round` |
| `CapsuleSize::Sm` | 112 × 34 | `data-size="112"` |
| `CapsuleSize::Md` | 180 × 34 | `data-size="180"` |
| `CapsuleSize::Auto` | 自适应 | 不套 filter，只走 CSS 涂层/高光 |

新增尺寸的流程：

1. 在 `scripts/build-glass.mjs` 的 `SHAPES` 加一条（id / 宽高 / 圆角 / 选择器）。
2. `node scripts/build-glass.mjs` 生成贴图与 `63-glass-svg.css`。
3. `node scripts/build-css.mjs` 重打 CSS 包。
4. 在 Rust 组件的尺寸枚举里加一档。

不要用一张 180 宽的贴图去套 112 宽的元素：会出现硬切或局部不滤波。

### 12.2 主题与材质的关系

- 位移/高光贴图是固定的，不随主题变；换主题不重建 filter。
- 涂层、模糊、饱和度仍由 `--lg-coating`、`--m-*-blur`、`--lg-vibrancy` 驱动。
- 想改折射强度，改 `glass-schema.js` 的 `amount/band` 后重新生成贴图；运行时改 CSS 变量不会改位移。

## 13. 图标

```rust
pub enum IconName { Grid, Sliders, Table, /* … 97 项 */ }
<Icon name=IconName::Grid size=16 />
```

- 97 个图标从 `core/icons.js` 的 path 表 1:1 移植；24 视框、`stroke-width` 由 `--ic-stroke` 控制。
- 找不到的名字在编译期就不存在；运行期没有 fallback 分支（旧库的字符串查表容易拼错）。
- 图标是 `aria-hidden="true"`；语义由父组件的 `label` / `aria-label` 提供。

## 15. 可访问性与键盘

- ARIA 由组件生成，调用方只给语义（`label`、`description`），不给 `role`/`aria-*`。
- 每个控件在 `02-迁移矩阵.md` 标注键盘图；至少覆盖：Tab 进出、方向键、Home/End、Space/Enter、Esc。
- 焦点可见：`:focus-visible` 必须保留；玻璃背景下也要有 3:1 对比。
- 降动态：`prefers-reduced-motion` 由 CSS 处理；弹簧与过渡读同一个媒体查询。
- 读屏：Toast/InlineMessage 用 `aria-live`；Dialog/Sheet 用 `aria-modal` + 焦点陷阱；进度类给 `aria-valuenow`。

## 16. 反模式（评审直接打回）

1. 组件里 `document.querySelector` / `getElementById`。
2. 组件里 `document.body.append`。
3. 在 render 期间读 `offsetHeight` / `getBoundingClientRect`。
4. 用 `inner_html` 塞图标或子结构。
5. 把 `HtmlElement` 当 prop（`NodeRef` 除外）。
6. 新增 `static mut` 或第三个全局单例。
7. 在 Rust 里写字面色值/px；需要新值时先加 token。
8. 为了“和旧库一样”而复刻已经证明有问题的结构（双栈、`dispose` 手动调用、`querySelectorAll` 扫表单）。
9. 用字符串拼 `class` 之外的样式；`class` 只允许追加，不替换组件类。
10. 把“能跑”当“完成”——没有键盘断言与视觉对照不算完成。

## 17. 版本与兼容

- `控件/Cargo.toml` 的 `version` 与 `pub const VERSION` 必须一致；CI 校验。
- 同 major：只加不改；旧 props 保留并标 `#[deprecated]`，至少留一个小版本。
- major：允许改 props 形状、删组件、改 DOM 契约；`变更.md` 逐条写迁移方法。
- 不承诺跨 major 的样式兼容；CSS 变量名尽量稳定，改名前先加别名。
- `install()` 把版本写到 `data-gd-version`，运行期可查；画廊页脚显示它，截图即证据。
